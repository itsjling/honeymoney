# Quality gates

Honeymoney 0.2.0 requires Python 3.14.6 and declares
`requires-python >=3.14,<3.15`.

The handoff gate runs:

```bash
./scripts/check.sh
```

It must cover Ruff formatting, Ruff lint, strict mypy, the full unittest suite,
branch coverage, package checks, and wheel and source builds. The project-wide
branch floor remains 87 percent. New workspace-storage modules join strict
typing when added; do not weaken the checked scope.

Use a focused synthetic test while changing code, then run the full gate once
at the end. Tests must not use live Ollama, live HKMA, private statements,
random corruption, skips, or expected failures.

## Required behavior

CLI acceptance in temporary synthetic workspaces is the main seam. Check human
and JSON output, schema 3, exit codes, exact layout, owner-only modes, durable
state, generated bytes, privacy bounds, and repeat safety.

Cover:

- no workspace, fresh setup, and reopened empty workspace;
- legacy rejection without writes;
- import failure, retry, replace, reset, retirement, and zero-row success;
- stable source, statement-transaction, and view-transaction identity;
- repeated equal rows, overlap membership changes, and duplicate decisions;
- corrections, rules, rates, profiles, mappings, date moves, and undated moves;
- cross-month transfers and links;
- empty, missing, edited, stale, and no-longer-implied views;
- direct input edits and `full_rebuild_required`;
- lock contention and stopped lock owners;
- every named staged write, file sync, replacement, directory sync, and
  workspace-index-last stop point;
- doctor audit, safe repair, hard-damage refusal, and post-fix audit;
- unsafe paths, symbolic links, unknown preserved files, and access modes;
- complete idle backup and empty-target restore; and
- deterministic equality between every automatic refresh and a clean full
  rebuild from the same durable state.

Direct contract tests may exhaust canonical serialization, import-record,
workspace-index, journal, and doctor states that the CLI cannot create safely.
They support, but do not replace, CLI acceptance.

Mature-workspace functional cases include as many as 1,000 import records,
about 200 transactions per record, one 5,000-row record, and 120 views. They set
no time or memory release threshold.

## Release archives

Install the built wheel and source archive offline into separate fresh Python
3.14.6 environments. Each must run:

1. setup and exact empty-layout and mode checks;
2. one synthetic import;
3. `imports list` and `imports show`;
4. its calendar-month view build;
5. `status --json` with schema 3; and
6. a healthy doctor audit.

Publish neither archive until both flows and runnable help pass.
